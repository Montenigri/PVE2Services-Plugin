PVE2 Drift OpenTofu Drift Detection

ℹ️ How drift detection works & why

How it works: your CI pipeline posts the output of tofu show -json to the ingestion endpoint after every apply (push model — no backend credentials needed here). Each resource is matched to the live cluster by a unique tag (pve2-managed-<hash>) that the module injects — never by vmid, which can change. A scheduled check then compares the last ingested declared state with the live state the Core Agent already collects.

Why: catch resources deleted or modified outside IaC, and attribute drift (cores, RAM, disk, node, vmid), without duplicating a Terraform provider's logic. The system proposes, the administrator decides: the plugin never applies anything.

Note: VMs live with a managed tag but no OpenTofu resource are reported to the Audit as unmanaged, not as drift. Notifications fire only on state transitions (opened/resolved), never on every check.
